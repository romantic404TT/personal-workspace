## 1. 一句话产品定义

> 一个用纯前端 mock 数据搭建的、可交互的"个人工作台"界面 Demo——集任务、日程、笔记、专注、数据看板与一个 AI 聊天助手于一体的现代工作台，用于展示产品设计与前端实现能力。

**非目标定义（同样重要）**：它不是真产品，不解决真实效率问题；它解决的是**"让访客在 60 秒内产生'我也想要这个'的冲动"**这一展示问题。所有功能取舍以此为最高裁判。

### 1.1 背景与目标

- **为什么现在做**：AI Copilot 类产品（Notion AI、Linear、Raycast、ChatGPT）已把"工作台 + 对话框"的心智教育完成，观众对这类界面有现成的审美与期待基准。
- **不做会怎样**：作品集停留在"todo app 换皮"层面，无法体现产品思维与细节把控。
- **做了能怎样**：一个链接、60 秒内建立"这个人懂产品也懂工程"的判断。

### 1.2 成功指标（Demo 语境下的诚实版本）

红线：不编造业务数据，本 Demo 无 DAU/转化率可承诺，指标改为**演示效果的可验证代理**：

| 指标 | 目标值 | 获取方式 |
|---|---|---|
| 访客点开 AI 抽屉比例 | ≥ 70%（如接免费分析如 Umami/GA） | 埋点事件 `ai_drawer_open` |
| 命令面板使用次数/访问 | ≥ 1.5 | `cmdk_open` |
| 演示平均停留 | ≥ 90s | 分析工具 |
| 整体验收口径 | 不懂技术的人打开链接，60 秒内主动点开 AI 聊天并说"这能装到我电脑上吗" | 人工观察 |

## 2. 目标用户与核心使用场景

| 用户角色 | 特征描述 | 核心诉求 | 使用场景 |
|---|---|---|---|
| **访客（真实用户）**：面试官、设计/产品同行、潜在客户 | 停留 1–3 分钟，边看边点 | 快速判断作者的产品思维、细节把控、工程完成度 | 收到链接 → 打开首页 → 点 AI 聊天 → 试命令面板 → 决定"这个人可以" |
| **演示者（你自己）** | 需在面试/路演中讲解 | 每个模块都有可讲的"故事点"，操作永不卡死 | 屏幕共享演示，被问"这个能扩展成真的吗" |
| **画面中的人（模拟用户）** | 虚构知识工作者 | 一屏管理当天工作 | 晨间规划、专注工作、AI 问答——全部为 scripted 演示 |

**核心使用场景（按演示优先级排序）**：

1. **"推开门"场景**：访客打开页面 2 秒内看到有信息量、有氛围的工作台首屏（时间问候语 + 今日概览）。
2. **"哇"场景**：呼出命令面板（⌘K），键入模糊词命中任务/笔记/应用——Raycast 式爽点。
3. **"AI"场景**：打开聊天窗口，点快捷指令，看到流式打字回复，回复中携带可点击的任务卡片——证明"AI 与工作台联动"的产品想象力。
4. **"细节控"场景**：深浅色切换、空状态插画、骨架屏、hover 微交互——供访客放大检视。

## 3. 需求边界：做什么 / 不做什么

| ✅ 做（In Scope） | ❌ 不做（Out of Scope） |
|---|---|
| React + TS 纯静态站点，本地 mock 数据（JSON/TS 常量） | 真实后端、API、数据库 |
| 工作台首屏 + 多模块子页面（任务/日程/笔记/专注/统计） | 真实登录、鉴权、多用户 |
| AI 聊天窗口：**本地脚本模拟**（预置问答 + 假流式输出） | 接入真实大模型、API Key、token 计费 |
| 命令面板（⌘K）全局搜索/跳转 | 跨设备数据同步、PWA 离线包 |
| 深浅色主题切换（仅 CSS 变量切换，不持久化真实偏好也行） | 浏览器插件、移动端原生 App |
| 响应式：桌面优先，平板可用，移动可看（降级为单列） | 手机上的一比一完美布局 |
| 交互状态齐全：加载/空/错误/成功各态演出 | 通知推送、日历真实订阅（ICS） |
| 数据可"会话内可变"（如勾选任务、发送消息，刷新后重置） | 真实持久化（localStorage 可做，但不做云同步） |
| 埋点式演示彩蛋（如"按 ? 查看快捷键"） | 国际化多语言（文案先只留中文，结构预留） |

**边界原则**：凡是"点下去会报错/会 404/会空白"的入口，一律删除或做成 mock 演出。Demo 的完整度 = 观众信任度。

## 4. 功能清单（P0 / P1 / P2）

优先级判断标准：**首屏可见性 × 演示冲击力 × 实现成本**。

### P0 —— 没有就不叫工作台，必须上线

| # | 功能 | 说明 | 理由 |
|---|---|---|---|
| P0-1 | 工作台首屏（Dashboard） | 问候语+日期、今日概览条、核心模块卡片聚合 | 门面；访客看到的第一屏决定第一印象 |
| P0-2 | AI 聊天窗口 | 完整形态见 §7，含流式模拟、快捷指令、上下文联动 | 本 Demo 最大差异化卖点，"AI Copilot 产品感"全靠它 |
| P0-3 | 任务清单模块 | 列表+分组（今日/本周/收集箱）、勾选完成、优先级标签、进度环 | 工作台心智的核心；也是 AI 联动的目标对象 |
| P0-4 | 命令面板 ⌘K | 模糊搜索任务/笔记/页面跳转、键盘上下选择、Esc 关闭 | Raycast 式爽点，成本极低、冲击力极高 |
| P0-5 | 全局导航框架 | 顶栏 + 侧边栏 + 页面路由骨架 | 一切模块的容器 |
| P0-6 | 响应式 + 深浅色主题 | 三档断点；主题一键切换且无闪烁 | 访客会拿手机打开看，也会检查暗色是否认真做了 |
| P0-7 | 空/加载/错误状态设计 | 所有含数据区域具备三态（可为演出效果预置） | "状态设计完备"是资深感的直接证据 |

### P1 —— 显著加分，强烈建议一期包含

| # | 功能 | 说明 | 理由 |
|---|---|---|---|
| P1-1 | 今日日程时间轴 | 纵向时间轴、会议块、"现在"游标 | 工作台第二刚需；视觉上极易做出高级感 |
| P1-2 | 快速笔记区 | 笔记卡片列表 + 详情页（mock markdown 渲染） | 展示内容型 UI 能力（列表/详情/富文本） |
| P1-3 | 数据看板/周报卡 | 本周完成任务柱状图、专注时长环图、习惯打卡热力图 | 图表是"信息可视化能力"的展示位 |
| P1-4 | 专注计时器（番茄钟） | 25/5 可跑通的倒计时 + 与"当前任务"关联显示 | 少数"真能跑起来"的交互，演示时最有生命力 |
| P1-5 | 快捷链接/常用应用格 | 图标网格 + hover 放大动效 | 首屏氛围感填充，成本低 |
| P1-6 | 天气/时间氛围模块 | 静态 mock 的"北京 ☀️ 22°" | 工作台标配，增强"真实桌面"错觉 |

### P2 —— 有余力再做，明确可砍

| # | 功能 | 说明 | 理由 |
|---|---|---|---|
| P2-1 | 习惯打卡独立页 | 从热力图点开详情 | P1-3 已覆盖展示价值 |
| P2-2 | 音乐播放器小组件 | 假封面+进度条 | 氛围加分但非工作台刚需，避免"什么都想要" |
| P2-3 | 系统设置弹层 | 主题/密度/快捷键开关的"设置页" | 展示设置界面能力，砍掉不影响主线 |
| P2-4 | 通知中心抽屉 | 假通知列表 | 锦上添花 |
| P2-5 | 引导蒙层（Demo Tour） | 首次进入的 4 步功能引导 | 双刃剑：演示时反而挡路，做成可跳过彩蛋更稳妥 |

**需求来源标注**：P0 全部来自"作品集要展示什么"的业务判断；模块选型（任务/日程/笔记/AI）参考 Notion 模板页、Linear 首页、Raycast 主界面、ChatGPT 对话形态。无用户调研数据（Demo 不需要，不虚标）。

**范围控制（防需求镀金）**：一期锁死 P0 + P1 共 13 项；若工期只有一周，砍 P1-3 / P1-5，AI 脚本保留 3 条。

## 5. 信息架构

### 5.1 站点地图

```
工作台 Demo
├── 首页 · Dashboard（唯一"聚合页"）
├── 任务 Tasks（列表 + 详情）
├── 日程 Calendar（今日时间轴 + 周视图占位）
├── 笔记 Notes（列表 + 详情）
├── 专注 Focus（计时器 + 本次会话记录）
├── 洞察 Insights（图表/周报）
└── 全局浮层（不属于任何页面）
    ├── 命令面板 ⌘K
    ├── AI 聊天抽屉（右侧滑出，任意页面可用）
    └── 主题切换 / 快捷键说明
```

### 5.2 导航结构

| 层级 | 位置 | 内容 |
|---|---|---|
| 顶栏（常驻） | 页面顶部 48–56px | 左：Logo+产品名；中：全局搜索框（点击唤起 ⌘K）；右：日期时间、AI 入口按钮、主题切换、头像（静态） |
| 侧边栏（常驻，可折叠） | 左侧 220px（移动端变底部 Tab / 汉堡抽屉） | 首页/任务/日程/笔记/专注/洞察 六项 + 底部"设置"（P2）；当前项高亮 |
| AI 抽屉 | 右侧覆盖层，不占路由 | 见 §7 |

### 5.3 模块关系（数据视角，全 mock）

- **任务**是中心对象：首屏"今日待办"卡、命令面板搜索结果、AI 聊天生成的任务卡、专注计时器"当前任务"、洞察页柱状图，五处**引用同一份 mock 任务数据**（会话内联动）。
- **日程**独立对象，仅在首屏"接下来"卡与 AI 排程建议中引用。
- **笔记**独立对象，仅被命令面板与 AI 引用。
- 这种"一处数据、多端呈现"是 Demo 最能体现产品架构感的地方——**必须做进 mock 层**。

## 6. 首页工作台布局

设计原则：**上轻下重、左主右辅、第一屏无滚动即见全貌**（1280px 宽下）。

| 顺序 | 区块 | 位置 | 展示内容 | 关键交互 |
|---|---|---|---|---|
| ① | 问候横幅 | 顶部通栏 | "早上好，李明 ☀️"（按系统时间 5–11/11–14/14–18/18+ 四档）+ 完整日期 + 一句话天气 + 今日进度条（已完成 3/8） | 无（营造氛围） |
| ② | 今日概览条 | 横幅下四宫格小卡 | 待办数 / 会议数 / 专注时长 / 连续打卡天数，各配迷你图 | 点击 → 跳转对应模块 |
| ③ | 今日待办 | 主栏左（约 60% 宽） | 任务列表：勾选框、标题、优先级点、截止时间、标签；底部"下一个：写周报 · 14:00"进度提示 | 勾选完成有划线+淡出动效；点标题进详情；"＋"内联新增 |
| ④ | 接下来 | 主栏右 | 日程迷你时间轴：今天下午 2 个会议块 + "现在"游标线 | 悬停显示参会人；点击跳日程页 |
| ⑤ | AI 助手召唤卡 | 右栏，紧跟"接下来" | 一张渐变卡片："问问工作台助手 · 试试'帮我规划下午'" + 打字机动态示例 | 点击 → 打开 AI 抽屉并预填该快捷指令 |
| ⑥ | 快速笔记 | 主栏左下 | 最近 3 条笔记卡（标题+摘要+更新时间） | "＋新建"内联输入框；点击进详情 |
| ⑦ | 专注中 / 开始专注 | 右栏 | 未启动：大按钮"开始专注 25:00"；运行中：倒数 + 当前任务名 + 完成/放弃按钮 | 真实可跑的倒计时（P1-4） |
| ⑧ | 本周概览 | 主栏底部 | 迷你柱状图（7 天完成量）+ 习惯打卡热力图缩略 | 点击跳洞察页 |
| ⑨ | 快捷链接 | 右栏底部 | 4–8 个应用图标格 | hover 上浮；点击不真跳转外部（用 tooltip "Demo 中"或打开 mock 详情页） |

**信息层级规则**：①②③④ 必须在首屏 100vh 内；⑤ 视觉权重仅次于③（用品牌渐变强调）；⑥–⑨ 可滚动露出。移动端重排为单列，顺序不变，②概览条改横向滑动。

## 7. AI 聊天窗口（本 Demo 的灵魂模块）

### 7.1 入口（4 个，覆盖不同心智路径）

| 入口 | 位置 | 行为 |
|---|---|---|
| 顶栏按钮 | 右上 "✨ AI 助手" | 开/关抽屉 |
| 快捷键 | `⌘J`（或 `/`） | 同上并聚焦输入框 |
| 首屏召唤卡 | 区块⑤ | 打开并预填快捷指令 |
| 局部入口 | 任务详情"让 AI 拆解"、编辑器"AI 润色"按钮 | 打开抽屉并自动携带该对象作为上下文 |

### 7.2 形态

- **右侧抽屉**：宽 400–420px（桌面）、覆盖层、页面内容不被挤压；右上角可切换为**居中大弹层模式**（沉浸对话，ChatGPT 式两段形态）。
- 平板：半屏覆盖；手机：全屏页。
- 内部三段式：头部（标题+清屏+全屏切换+关闭）/ 消息流（滚动区）/ 输入区（固定在底）。
- 历史会话：头部左侧下拉，展示 3 条 mock 历史会话（"昨天的周报草稿"等），切换即加载对应 mock 消息——**体现"AI 有记忆"的产品设定**。

### 7.3 消息类型（6 种，全部要能在 Demo 中出现）

| 类型 | 说明 |
|---|---|
| 用户消息 | 右侧气泡 |
| AI 流式文本 | 左侧，打字机逐字输出，可中途"停止生成" |
| AI 建议问题 | AI 回复下方 2–3 个灰色 chips，点击即发送 |
| 工作台卡片消息 | AI 回复中内嵌**可交互卡片**：任务卡（带"添加到今日"按钮）、日程卡、笔记摘要卡 |
| 操作确认条 | 当 AI"要改动工作台数据"时，消息下方出现"✓ 应用到今日待办 / ✕ 忽略"，点 ✓ 后任务区真实（会话内）新增——**Demo 最强时刻** |
| 系统/错误消息 | 居中灰字："已为你清空" / "网络异常" + 重试按钮 |

### 7.4 快捷指令（输入框上方 chips + `/` 呼出菜单）

| 指令 | 模拟回复要点 |
|---|---|
| 帮我规划今天下午 | 引用 mock 日程空隙 + 未完成任务 → 生成 3 张任务卡 + 确认条 |
| 总结今天做了什么 | 引用任务完成状态 → 一段文本 + "生成日报"按钮（点击弹 toast"已存为笔记"） |
| 这个任务怎么拆？（带任务上下文） | 将选中任务拆成 3 个子任务卡 |
| 帮我想个产品名 | 纯文本 + 建议问题 chips |
| 查一下明天有什么会 | 引用日程数据回答 |

实现方式：**规则匹配**（关键词命中 → 播放预写回复脚本），非真 AI。每条脚本按 §7.3 混搭消息类型，展示面铺满。

### 7.5 上下文联动（产品想象力核心）

- 输入框上方有**上下文引用条**：`📌 来自：任务「写 Q3 周报」`，可 × 移除。来源：从任务/笔记详情页点 AI 按钮时自动带入。
- AI 回复生成的任务卡，经用户确认后写入共享任务数据 → 首屏③区块同步出现，附一次高亮描边动画。
- 页面感知（演出即可）：抽屉顶部副标题显示"当前页面：任务"，让访客感觉 AI 知道自己所在位置。

### 7.6 状态设计

| 状态 | 表现 |
|---|---|
| 空状态 | 居中吉祥物图标 + "我是你的工作台助手，可以帮你规划、总结、拆解任务" + 快捷指令 chips（**绝不显示空白**） |
| 发送中 | 用户气泡即时上屏，气泡尾部灰色 ✓✓ |
| AI 思考/流式 | 三点跳动动画 ≤1.2s 后开始逐字输出；输出时自动滚底，用户上滑则停止跟随并出现"↓ 回到底部"浮标 |
| 停止生成 | 输出中发送区变为"■ 停止"，点击截断并显示"已停止" |
| 错误态 | 预置演示脚本：输入"（故意）报错"或第 N 次请求 → 显示"⚠️ 生成失败" + 重试按钮，点重试成功——**主动演示错误恢复能力** |
| 兜底回复 | 未命中关键词的输入 → 1 条万能回复（承认 Demo 身份 + 引导快捷指令），**诚实且是加分项** |
| 历史记录 | mock 3 条会话，可切换、可删除（会话内） |

## 8. 关键交互与状态汇总

| 交互 | 规则 | 状态反馈 |
|---|---|---|
| ⌘K 命令面板 | 任意页面呼出；输入即模糊过滤（任务/笔记/页面/操作四组）；↑↓选择、Enter 执行、Esc 关闭；展示最近使用 | 打开即聚焦；无结果显示"未找到「xxx」"空态 |
| 任务勾选 | 乐观更新，先动效后（假）保存 | 划线+透明度衰减，概览条计数与首屏进度条同步 |
| 主题切换 | 顶栏一键，全站 CSS 变量过渡 200ms | 图标形变（日↔月），无白闪 |
| 模块卡跳转 | 卡片标题右侧 hover 出现 "→ 查看全部" | 路由切换 + 侧边栏高亮同步 |
| 骨架屏 | 首次进入各页显示 600–900ms 骨架（故意演出加载） | shimmer 动画 |
| 悬停/聚焦 | 卡片 hover 上浮 2px + 阴影；键盘 Tab 焦点环清晰可见 | 微交互一致性 > 花哨 |
| 移动端导航 | 侧边栏 → 底部 Tab（首页/任务/AI/更多） | AI 抽屉 → 全屏 |
| 会话内持久 | 刷新重置为初始 mock（可接受）；localStorage 为可选增强 | 演示前刷新一次即为干净状态 |

## 9. 视觉风格与设计原则

**关键词**：现代 · 简洁 · 高级 · 呼吸感。参考基线：Linear 的克制深色质感、Notion 的内容友好、Raycast 的通透玻璃感、ChatGPT 的对话秩序。

| 原则 | 落地要求（给设计师/前端的方向，不指定具体值） |
|---|---|
| 中性色打底，单一强调色 | 灰阶承担 90% 界面；一个品牌色（建议靶蓝/紫系）只用于：主 CTA、AI 元素、选中态 |
| AI 有专属视觉身份 | AI 相关一律带品牌渐变 + ✨ 图形语言，与自然模块一眼区分 |
| 圆角与玻璃质感克制使用 | 卡片大圆角；命令面板/AI 抽屉可用背景模糊，但不满屏堆特效 |
| 8pt 栅格 + 强留白 | 模块间距一致；宁可"空"不要"挤" |
| 排版三级 | 数字用大号等宽/半粗体（概览条），标题中号，正文小灰；中文字体走系统栈 |
| 动效服务于反馈 | 只在状态变化处动（勾选、出卡片、切页），时长 150–300ms，无自嗨动画 |
| 暗色模式是第二主场 | 深色不是反色，需单独调校层级（尤其 Demo 截图观感） |
| 假数据像真数据 | 文案禁用 "test/示例1"，全部写成可信人名、任务名、时间 |

## 10. 技术选型建议（只建议，不写代码；最终由技术侧定）

| 层 | 建议 | 一句话理由 |
|---|---|---|
| 框架 | Vite + React 18 + TypeScript | 启动快、静态产物小，业界默认 |
| 路由 | React Router（或文件式路由） | 多页面信息架构需要真 URL |
| 样式 | Tailwind CSS + CSS 变量做主题 | 深浅色切换成本最低，设计还原快 |
| 组件基础 | shadcn/ui（Radix 之上） | 无头、可完全定制、自带高级感与 a11y |
| 图标 | Lucide | 与 shadcn/Linear 气质一致 |
| 动画 | Framer Motion（关键处）+ CSS transition | 卡片进出、抽屉、流式光标 |
| 图表 | Recharts（或 Tremor 组件库） | 图表需求轻量，不值得上重型方案 |
| 状态 | Zustand（跨模块共享 mock 任务数据） | 服务端状态不存在，Context 或 Zustand 够用 |
| Mock 数据 | 静态 TS 模块 + 一个内存"假 store"；AI 回复用关键词路由脚本 | 明确无网络请求，避免演示翻车 |
| Markdown | react-markdown（笔记详情） | 现成 |
| 部署 | Vercel / Netlify / GitHub Pages | 静态拖拽即上线 |
| 质量 | ESLint + Prettier；可选 Playwright 冒烟 3 条链路 | 作品集仓库本身就是展示物 |

## 11. 组件拆分建议

```
App（主题/路由/全局快捷键）
├─ layout/  AppShell · TopBar · SideNav · PageHeader
├─ dashboard/  GreetingBar · StatOverview(×4) · TodoCard · AgendaMiniTimeline
```
